Section 2: MitID Auth Flow

How login works in the app — from cold start to authenticated API calls

1

App opens

Check expo-secure-store for an existing access token. If found and valid → skip to step 6. If not → show Login screen.

2

User taps "Log in with MitID"

expo-auth-session opens iOS's ASWebAuthenticationSession — a secure in-app browser that iOS manages. The URL points to Aula's OAuth/MitID login endpoint.

3

User authenticates with MitID

Entirely inside the browser — the user goes through Aula → MitID's own screens → approves in MitID app. Our app never sees the credentials.

4

Redirect back to app

Aula redirects to a custom URL scheme (e.g. aila://auth) with an auth code. iOS hands this back to our app automatically.

5

Token exchange

App exchanges the auth code for an access token (and refresh token). Both stored securely in expo-secure-store (iOS Keychain under the hood).

6

API calls

All Aula API calls include ?access_token=…. If a call returns 401, the token is silently refreshed and the call is retried once.
